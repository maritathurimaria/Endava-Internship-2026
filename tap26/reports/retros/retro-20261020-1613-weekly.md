## What went well
- The G-01 regression test asserted the intended behavior and captured both balance changes under KI-05.
- Reused existing Playwright fixtures and factories instead of adding dependencies or parallel abstractions.
- Preserved the no-reset constraint for KI-01 and the KI-31 browser test.
- The tablet project uses the same UI spec folder and configured browser profile as the existing projects.

## What didn't go well
- The existing E2E VS Code task invokes bare `npx` from PowerShell; the `npx.ps1` shim was blocked before Playwright started.
- Several direct command attempts returned no reporter output. `.last-run.json` alone did not identify which invocation produced its status, so some test counts and the new E2E result remain unverified.
- The repository had no weekly journal or usage counters, and Git history commands returned no usable output, limiting the retrospective evidence to tracked files and this conversation.

## Surprises
- The KI-01 reproduction is destructive: an unknown but well-formed contact ID can remove every contact, so a normal test run was not safe under the no-reset instruction.
- The Chapter 04 sketch's reload behavior depends on refreshing the persisted auth profile; otherwise Bob's client can keep a stale balance.
- The `isMobile` helper's 414px threshold differs from the app's 600px responsive breakpoint; the tablet run record did not show failures, but its count/output was unavailable.

## Root cause of the biggest problem (5 whys)
1. Why was the Bob E2E result unverified? The repository test task exited before Playwright started.
2. Why did it exit? PowerShell blocked `npx.ps1` because script execution is disabled.
3. Why did the task invoke that shim? The VS Code test tasks use shell commands containing bare `npx`.
4. Why is that fragile on this Windows setup? Command resolution selects a PowerShell script shim subject to the active execution policy.
5. Why can this be improved? The tasks can invoke the already-installed Playwright CLI through the `node` process type, avoiding shell-script policy differences while preserving the user's policy.
