## Recent learnings
- L-002 Clicking "Sign Up" can be swallowed by blur validation — Retry the navigation click until the URL changes (`openSignUp` uses `expect(...).toPass()`), never add hard waits.
- L-003 Re-clicking the selected feed tab does not refetch — When the tab is already selected, reload the page to trigger the request (see `openFeedAndRead` in transaction-feeds.spec.ts).
- L-004 Start waiting for a response before the action — `const res = waitForApi(page, …); await action(); await res;` — the Playwright equivalent of `cy.intercept().as()` + `cy.wait()`.
- L-005 `pkill -f <pattern>` can kill the shell that runs it — Kill by PID or use a pattern that cannot match the invoking command (e.g. `pgrep -f "[p]laywright test"`).
- L-006 Document actual behaviour, then fix deliberately — When the API misbehaves (e.g. unknown id updates the first record), the OpenAPI spec records the real behaviour and links a KI id, while tests assert the correct behaviour under test.fail('KI-xx') (see D-005); fixes happen as explicit changes so tests, spec and docs move together.
- L-007 Cypress spec title points at the wrong route — Coverage by title matching is heuristic; check the request actually made. Good first-fix exercise for students.
- L-008 VS Code tasks: use process type for node, end dev task on Vite output — Tasks that run node -e should be type 'process' with args (avoids PowerShell/cmd quoting); the RWA backend logs nothing when it starts listening, so a background 'yarn dev' task must end on Vite's 'ready in'.
- L-009 Verify mocks and fixtures by byte-comparing with the real API — After building a fixture or a stateful mock route, diff it against the real response (seeded DB, same user) — JSON.stringify equality caught ordering bugs that a schema check would miss
- L-010 Factories must omit undefined keys for notification variants — Build notification objects without the keys of other variants (compact the object); test that buildNotification({kind:'like'}) has no 'status' property
- L-011 Killing npx does not stop the server it started — Start servers with node <bin> directly, or find the listener by port/args (ps -eo pid,args | grep '[v]ite') and kill that PID
